## 5.2 Runtime Overhead

Results of this section is in `out/spec_overhead` and `out/adversarial`. 

`out/spec_overhead/{test|train|ref}/overhead.png` corresponds to Figure 7. 
As we noted in the artifact appendix, notice that the paper reports the results from running the ref input set.
The default `./run.sh all` would default to running the train input set. 
From our experiences, the `train` set and the `ref` set agrees on the order of magnitude while the exact statistics would differ. 
To run the ref input set, please use `./run.sh spec_overhead --input ref`.

## 6.1 Process Lifecycle Variability

Results of this section is in `out/process_launch`.

`out/process_launch/figures` contains all the figures for this section.
* `out/process_launch/figures/control_distribution.png` corresponds to Figure 12. 
* `out/process_launch/figures/fix_ccdf.png` corresponds to Figure 13. 
* `out/process_launch/figures/tracepoint_overhead_density.png` corresponds to Figure 14. 

Additionally, it would be useful to download and inspect some trace visualizations in an interactive viewer.
`out/process_launch/speedscope` contains all the trace visualizations for this section.
`out/process_launch/speedscope/trace-256` contains traces before applying our fix. 
* Viewing `trace-256.iter*.mean.speedscope.json` should show the a normal latency process launch instance reported in Figure 11. 
* Viewing `trace-256.iter*.slowest5.speedscope.json` should show the batched RCU work reported in Figure 15. 
* Viewing `trace-256.iter*.slowest1.speedscope.json` should show the ping-pong tail latency case reported in Figure 16. 
* Viewing `trace-256-fix.iter*.slowest1.speedscope.json` should show the ping-pong tail latency is eliminated. This is reported as text in the paper. 

To view these traces, download these traces to your own machine, open [speedscope.com](speedscop.com) and drop in the traces.
